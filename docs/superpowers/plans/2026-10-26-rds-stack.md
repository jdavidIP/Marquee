# RDS Stack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Provision a private, SSL-only PostgreSQL 16 RDS instance in a new `MarqueeDataStack`, reachable from the app host only, without changing any existing resource.

**Architecture:** `MarqueeStack` exposes its VPC and host security group; `Program.cs` passes them into a new `MarqueeDataStack`, which adds two isolated subnets, a database security group, a parameter group and the instance. Verification is by build, synth, template inspection and `cdk diff` (there is no CDK test project, as with `MarqueeCleanupStack`), then a live check from the host.

**Tech Stack:** AWS CDK v2 for .NET (`Amazon.CDK.Lib` 2.271.0), RDS for PostgreSQL 16, CloudFormation `ssm-secure` dynamic references.

**Spec:** `docs/superpowers/specs/2026-10-26-rds-stack-design.md`

## Global Constraints

- Region `ca-central-1`; `infra/` is never added to `Marquee.sln`.
- `cdk synth` must work with no AWS credentials (CI runs `npx --yes aws-cdk@2.1143.0 synth --quiet -c alertEmail=ci@example.invalid`): no lookups.
- Every `cdk` command takes `-c alertEmail=jdavidip2022@gmail.com` (the deployed value; a different one swaps the SNS subscription) and needs `eval "$(aws configure export-credentials --format env)"` in the same Bash command.
- `cdk deploy` is run by the owner (`! ... --require-approval never`), never by Claude; Git Bash commands with `/paths` need `MSYS_NO_PATHCONV=1`.
- Nothing in `MarqueeStack` may be replaced or modified; it may only gain outputs/exports.
- Commits only after the owner confirms each one; no attribution lines; Conventional Commit prefixes.

## Review Focus

1. **`MarqueeStack` changing more than outputs** (a renumbered subnet, a replaced host) — expected: the diff shows only new `Outputs`/exports. Pinned by Task 1 Step 6.
2. **A cross-stack cycle**: a rule for the host's security group created inside `MarqueeStack` (e.g. an egress rule from `connections.allowTo`), which makes `MarqueeStack` depend on `MarqueeDataStack` — expected: synth succeeds and `MarqueeStack`'s template gains no `AWS::EC2::SecurityGroup*` resource. Pinned by Task 1 Steps 4–5.
3. **Synth needing AWS access** (a lookup or a resolved SSM value) — expected: synth succeeds with credentials unset. Pinned by Task 1 Step 4.
4. **The Free Plan refusing 7-day backups, or the password breaking RDS's character rules** — expected: the create fails and rolls back; fall back to 1 day (spec decision 6) or rotate the password first. Covered by Task 2 Steps 1 and 4.
5. **A non-SSL connection being accepted** — expected: refused, because `rds.force_ssl = 1`. Pinned by Task 2 Step 5.

### Task 1: `MarqueeDataStack`

**Files:**
- Create: `infra/MarqueeDataStack.cs`
- Modify: `infra/MarqueeStack.cs` (expose two properties; assign them where `vpc` and `hostSg` are created, lines 67 and 79)
- Modify: `infra/Program.cs` (capture the `MarqueeStack` instance; add the data stack after it)

**Interfaces:**
- Produces on `MarqueeStack`: `public Vpc Vpc { get; }` and `public SecurityGroup HostSecurityGroup { get; }`.
- Produces: `public MarqueeDataStack(Construct scope, string id, IVpc vpc, ISecurityGroup hostSecurityGroup, IStackProps props)`, created in `Program.cs` as
  `new MarqueeDataStack(app, "MarqueeDataStack", main.Vpc, main.HostSecurityGroup, new StackProps { Env = env, TerminationProtection = true });`
- Produces outputs `DbEndpoint` (address), `DbPort`, `DbSecurityGroupId` (used by #161).

- [ ] **Step 1: Expose the VPC and host security group on `MarqueeStack`**

Assign the existing locals to the two new properties; no other change to that file.

- [ ] **Step 2: Write `infra/MarqueeDataStack.cs`**

Comment style as in `MarqueeAuthStack.cs` (why the stack is separate, why the subnets are hand-made). Values, all from the spec:

| Piece | Value |
|---|---|
| Subnets | `Subnet` constructs (each brings its own route table with only the local route): `DbSubnetA` `10.0.100.0/24` in `ca-central-1a`, `DbSubnetB` `10.0.101.0/24` in `ca-central-1b`, `VpcId = vpc.VpcId` |
| Subnet group | `SubnetGroup` over exactly those two subnets |
| Security group | `DbSg` in `vpc`, `AllowAllOutbound = false`; `DbSg.AddIngressRule(hostSecurityGroup, Port.Tcp(5432), ...)`. Do **not** use `connections.allowTo`/`allowFrom` on the host group (cycle, Review Focus 2) |
| Engine | `DatabaseInstanceEngine.Postgres(... PostgresEngineVersion.Of("16.15", "16") ...)`, `AutoMinorVersionUpgrade = true` |
| Parameter group | engine as above; `rds.force_ssl` = `1`, `timezone` = `America/Toronto` |
| Instance class | `db.t4g.micro` (`InstanceClass.BURSTABLE4_GRAVITON`, `InstanceSize.MICRO`) |
| Credentials | `Credentials.FromPassword("marquee", SecretValue.SsmSecure(PasswordParameter, PasswordParameterVersion))` with constants `PasswordParameter = "/marquee/prod/POSTGRES_PASSWORD"` and `PasswordParameterVersion = "1"` (current version, checked 2026-10-26), plus a comment saying a rotation bumps it (spec, "Calls made in review") |
| Database | `DatabaseName = "marquee"` |
| Storage | 20 GB, `MaxAllocatedStorage = 40`, `StorageType.GP3`, `StorageEncrypted = true` |
| Availability | `MultiAz = false`, `PubliclyAccessible = false` |
| Backups | `BackupRetention = Duration.Days(7)`, `PreferredBackupWindow = "08:00-08:30"`, `PreferredMaintenanceWindow = "mon:08:30-mon:09:00"` |
| Protection | `DeletionProtection = true`, `RemovalPolicy = RemovalPolicy.SNAPSHOT` |
| Off | no Performance Insights, no enhanced monitoring, no `CloudwatchLogsExports` |

- [ ] **Step 3: Wire it into `Program.cs`**

Change `new MarqueeStack(...)` to `var main = new MarqueeStack(...)` and add the `MarqueeDataStack` line from Interfaces after it.

- [ ] **Step 4: Build, and synth with no credentials**

Run: `cd infra && dotnet build && env -u AWS_ACCESS_KEY_ID -u AWS_SECRET_ACCESS_KEY -u AWS_SESSION_TOKEN -u AWS_PROFILE npx --yes aws-cdk@2.1143.0 synth --quiet -c alertEmail=ci@example.invalid`
Expected: build with 0 errors; synth exits 0 and writes `cdk.out/MarqueeDataStack.template.json`.

- [ ] **Step 5: Inspect the synthesized templates**

Run: `grep -oE '"(Engine|EngineVersion|DBInstanceClass|PubliclyAccessible|MultiAZ|BackupRetentionPeriod|PreferredBackupWindow|DeletionProtection|DeletionPolicy|StorageType|StorageEncrypted|AllocatedStorage|MaxAllocatedStorage|DBName|MasterUsername|CidrBlock|AvailabilityZone|rds.force_ssl|timezone)": ?[^,}]*' infra/cdk.out/MarqueeDataStack.template.json | sort | uniq -c` and `grep -o 'ssm-secure:[^}]*' infra/cdk.out/MarqueeDataStack.template.json`
Expected: every value in the Step 2 table (`postgres`, `16.15`, `db.t4g.micro`, `false`, `false`, `7`, `08:00-08:30`, `true`, `Snapshot`, `gp3`, `true`, `20`, `40`, `marquee`, `marquee`, both CIDRs and AZs, `1`, `America/Toronto`) and `ssm-secure:/marquee/prod/POSTGRES_PASSWORD:1`.
Run: `grep -c '"AWS::EC2::SecurityGroup' infra/cdk.out/MarqueeStack.template.json`
Expected: the same count as on `main` (one: the host group) — no new rule landed in `MarqueeStack`.

- [ ] **Step 6: `cdk diff` against the live account**

Run: `cd infra && eval "$(aws configure export-credentials --format env)" && npx --yes aws-cdk@2.1143.0 diff MarqueeStack MarqueeDataStack -c alertEmail=jdavidip2022@gmail.com`
Expected: `MarqueeStack` shows only new `Outputs` (exports for the VPC id and the host security group id), with no `[~]` or `[-/+]` on any resource; `MarqueeDataStack` shows only `[+]` resources. Any change to an existing `MarqueeStack` resource: stop and bring it to the owner.

### Task 2: Deploy, verify live, and record it

**Files:**
- Modify: `DEPLOYMENT.md` (§ Phase 3)
- Modify: `docs/deployment/runbook.md` (password rotation)
- Modify: `docs/deployment/verification-log.md` (new "RDS stack (#160)" section)

**Interfaces:**
- Consumes: stack `MarqueeDataStack` and its outputs `DbEndpoint`, `DbPort`, `DbSecurityGroupId` (Task 1).

- [ ] **Step 1: The owner checks the password against RDS's rules** (spec step 0)

Owner runs: `! MSYS_NO_PATHCONV=1 aws ssm get-parameter --name /marquee/prod/POSTGRES_PASSWORD --with-decryption --query Parameter.Value --output text | python -c "import sys;v=sys.stdin.read().rstrip('\n');print(len(v), 'OK' if 8<=len(v)<=128 and all(33<=ord(c)<=126 and c not in '/\"@' for c in v) else 'NOT OK')"`
Expected: `OK`. `NOT OK`: stop; rotation comes first (spec, "Calls made in review").

- [ ] **Step 2: The owner deploys `MarqueeStack` (exports only)**

Owner runs: `! cd infra && eval "$(aws configure export-credentials --format env)" && npx --yes aws-cdk@2.1143.0 deploy MarqueeStack -c alertEmail=jdavidip2022@gmail.com --require-approval never`
Expected: `UPDATE_COMPLETE`; the host's instance id is unchanged (`aws ec2 describe-instances --instance-ids i-025489e6f2ed90173 --region ca-central-1 --query 'Reservations[0].Instances[0].State.Name'` still answers).

- [ ] **Step 3: The owner deploys `MarqueeDataStack`**

Owner runs the same command with `MarqueeDataStack --exclusively`.
Expected: `CREATE_COMPLETE` after roughly 10 minutes.

- [ ] **Step 4: If the create failed on backup retention**

A free-tier restriction on `BackupRetentionPeriod` rolls the create back. Set `BackupRetention = Duration.Days(1)` (spec decision 6) with a one-line comment saying why, commit after the owner confirms (`fix: keep RDS backups within the Free Plan limit (#160)`), and repeat Step 3. Any other failure: stop and read the CloudFormation event.

- [ ] **Step 5: Verify from the host**

Through Session Manager on the host (owner, or `aws ssm send-command` read-only output):
- `docker run --rm -e PGPASSWORD="$(grep ^POSTGRES_PASSWORD= /opt/marquee/.env | cut -d= -f2)" postgres:16 psql "host=<DbEndpoint> dbname=marquee user=marquee sslmode=require" -c 'SHOW timezone;' -c 'SHOW ssl;'`
  Expected: `America/Toronto` and `on`.
- The same with `sslmode=disable`.
  Expected: refused, with a `pg_hba.conf` error naming SSL or encryption as off (exact wording varies by minor version).

- [ ] **Step 6: Verify from outside**

From the owner's laptop: `nslookup <DbEndpoint>` resolves to a `10.0.10x.x` address, and `psql "host=<DbEndpoint> ..."` (or `Test-NetConnection <DbEndpoint> -Port 5432`) does not connect.
